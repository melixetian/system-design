# system-design

My interactive book for System Design

Учебник для подготовки к System Design интервью на Senior Backend Engineer. Цель курса — научиться уточнять требования, проектировать систему, объяснять компромиссы и пересматривать архитектуру при изменении условий.

## План курса

| Тема | Что разбираем |
| --- | --- |
| [01. Как начать интервью](lessons/01-interview-fundamentals/) | Уточняющие вопросы, границы задачи, функциональные и нефункциональные требования. |
| 02. Оценка нагрузки | Средний и пиковый QPS, чтение и запись, объём хранения и сетевой трафик. |
| 03. Первая архитектура | API, модель данных, путь запроса, балансировка и горизонтальное масштабирование. |
| 04. Хранение данных | Индексы, транзакции, выбор БД, репликация, шардирование и согласованность. |
| 05. Кэширование | Локальный кэш, Redis, CDN, TTL, инвалидация и отказ кэша. |
| 06. Асинхронная обработка | Очереди, воркеры, потоки событий, повторная доставка, идемпотентность и порядок сообщений. |
| 07. Надёжность | Таймауты, повторные попытки, circuit breaker, ограничение нагрузки, деградация и наблюдаемость. |
| 08. Обсуждение архитектуры | Обоснование решений, компромиссы, управление временем и изменение требований по ходу интервью. |

## Как заниматься

Уроки выходят по одному в `lessons/`. В каждом уроке разбираем одну идею на примере. В конце темы — контрольная из 3–5 вопросов с последующим разбором ответов.

После теории переходим к [практике](practice/). Начинаем с совместного проектирования, затем решаем задачи с меньшим количеством подсказок и проводим пробные интервью по 45–60 минут.
