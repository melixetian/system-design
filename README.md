# system-design

My interactive book for System Design

Учебник для подготовки к System Design интервью на Senior Backend Engineer. Цель курса — научиться уточнять требования, проектировать систему, объяснять компромиссы и пересматривать архитектуру при изменении условий.

| [02. Оценка нагрузки](lessons/02-load-estimation/) | Средний и пиковый QPS, чтение и запись, объём хранения и сетевой трафик. |

## Выбор компонентов на интервью

В каждой задаче сначала выбираем простую рабочую схему. Для каждого компонента называем операцию, нагрузку, нужную гарантию и условие, при котором выбор придётся пересмотреть. Сравниваем с одной разумной альтернативой. Учитываем отказ и стоимость эксплуатации.

- **3.3–3.4. Путь запроса и масштабирование.** Разводим роли балансировщика, API gateway и приложения. На примерах определяем, когда появляются отдельный воркер, объектное хранилище и поисковый индекс.
- **4.3. Выбор между SQL и NoSQL.** Сравниваем PostgreSQL, MongoDB, Cassandra и ClickHouse по паттернам чтения и записи, транзакционным требованиям, модели данных и цене масштабирования. Отдельно проверяем, хватит ли одной БД для транзакций и отчётов при заданном объёме.
- **5.1–5.3. Кэширование.** Сравниваем локальный кэш, Redis и CDN. Для Redis указываем роль, допустимую свежесть, политику вытеснения и нагрузку на источник данных при отказе кэша.
- **6.2. Выбор RabbitMQ, Kafka или SQS.** Разбираем маршрутизацию задач, подтверждения и повторы, хранение истории, повторное чтение событий и несколько независимых групп потребителей. Отдельно разбираем Celery как Python-фреймворк для отправки и выполнения фоновых задач через брокер.
- **8.2. Сравнение вариантов.** Даём короткое обоснование на интервью и пересматриваем выбор, если в задаче меняется одно требование. Например, подтверждённые брони хранятся в PostgreSQL, а необходимость Redis или ClickHouse проверяем отдельно по нагрузке и запросам к данным.

## Как заниматься

Уроки выходят по одному в `lessons/`. В каждом уроке разбираем одну идею на примере. В конце темы — контрольная из 3–5 вопросов с последующим разбором ответов.

После теории переходим к [практике](practice/). Начинаем с совместного проектирования, затем решаем задачи с меньшим количеством подсказок и проводим пробные интервью по 45–60 минут.
